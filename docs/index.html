5 · What this demo is, and what it is not

Model

  • Discrete-event simulation: time advances from event to event, not in fixed ticks.
  • A server owns a fixed number of worker threads; each worker serves one slice at a time.
  • A slice takes remaining_size / bandwidth simulated seconds plus a configurable per-dispatch overhead.
  • Round Robin caps a slice at the quantum; unfinished requests re-enter the queue.
  • WFQ-like uses a priority-derived weight and virtual finish tags; it is a simplified approximation, not a byte-accurate implementation of weighted fair queueing.

Honest scope

  • No real transfer, sockets, threads or disk I/O are involved; the numbers are properties of the model.
  • Bandwidth values are inputs from the workload file, not measured link speeds.
  • Metrics characterise the synthetic workloads shipped with the project and the parameter ranges reachable in this UI. They are not benchmark results from a deployed server.
  • Workloads marked “C++ CLI” were produced by ./simulator --generate-sample … --n N --seed S; the boundary workload is hand-authored to exercise ties and limit cases.
  • The browser-side generator uses a small local PRNG and is labelled accordingly; it does not reproduce the CLI's std::mt19937 sequence. Use the bundled CLI datasets for exact reproduction.
  • No analytics, no cookies and no requests to third parties: every asset is served from this repository.
Equivalence with the command-line simulator

The JavaScript core (engine.js) mirrors the C++ modules scheduler, simulation_engine and metrics operation by operation, including the heap procedures used by the C++ standard library implementation and the tie-breaking rules among equal keys. Across 12 reference configurations and all five schedulers the port reproduces 2455 per-request rows and 60 summary rows of the command-line output; the largest deviation observed is 4.99e-5, inside the four-decimal rounding of the CSV the CLI writes. You can re-run the whole comparison yourself on the equivalence check page: it replays those twelve workloads in your browser against the CSV files recorded from the command-line simulator, which are stored as plain text in oracle_bundle.js.
